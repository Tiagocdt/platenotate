# project has had came from here, and an unpinned build cannot be reproduced after the
# fact: when a collaborator reports a crash, "which pywebview did that .exe contain?"
# has to have an answer. desktop.py is written against these exact versions (pywebview
# 6.2.1's winforms backend, and the pythonnet load path it drives). Bump them
# deliberately, then check the Windows GUI probe in CI is still green.

pythonnet==3.1.0 ; sys_platform == "win32"     # pywebview's winforms backend needs it
clr-loader==0.3.1 ; sys_platform == "win32"    # …and this hands Python.Runtime.dll to .NET
